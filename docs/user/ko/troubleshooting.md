# 문제 해결과 진단 로그

## 진단 명령

문제를 보고하기 전에 다음 명령을 실행합니다.

```powershell
piu-rise-controller -vv doctor
```

애플리케이션 버전, 운영체제, 관리자 권한 상태, 설정 경로, 로그 경로,
설정 스키마 및 MIDI 포트를 출력합니다. 관련 없는 키보드 입력은 기록하지
않습니다.

## 로그

애플리케이션은 `doctor`가 `logs=`로 표시한 경로에 일별 로그 파일을
기록합니다. 일반 로그에는 수명 주기, 매핑, 출력 전환 및 오류 정보가
포함됩니다. 구형 장치 식별에 필요한 raw MIDI 바이트는 `-vv monitor`에도
출력됩니다. MIDI 포트 이름에 장치별 또는 계정별 접미사가 있을 수 있으므로
공유 전에 파일을 검토하십시오.

## MIDI 포트가 없거나 선택자가 모호한 경우

- 다른 MIDI 장치를 분리하고 `list`를 다시 실행합니다.
- `--input`에 더 길고 고유한 문자열을 사용합니다.
- MIDI 포트와 DAW 포트가 함께 보이면 MIDI 포트를 선택합니다.

## 키가 눌린 채 남은 경우

1. 모든 물리 패드에서 손을 뗍니다.
2. 컨트롤러 콘솔에서 Ctrl+C를 누릅니다.
3. 프로세스가 이미 종료됐다면 관리자 콘솔에서
   `piu-rise-controller release-all`을 실행합니다. Windows에서 여전히
   활성 상태라면 해당 물리 키보드 키를 한 번 눌렀다 뗍니다.
4. 로그를 저장하고 정상 종료, 장치 분리 또는 강제 종료 중 어떤 상황이었는지
   기록합니다.

프로세스 강제 종료나 전원 차단 이후에는 어떤 애플리케이션도 Release All을
보낼 수 없습니다. 입력이 활성화된 상태에서 강제 종료하지 마십시오.

## RISE에서 키를 받지 못하는 경우

- `elevated=true`인지 확인합니다.
- 다른 관리자 권한 애플리케이션에서 `output-test`를 확인합니다.
- RISE에 설정된 키 바인딩을 확인합니다.
- 컨트롤러가 `--dry-run`으로 실행 중이지 않은지 확인합니다.
- 컨트롤러 로그와 정확한 설정 파일을 함께 보관합니다.
